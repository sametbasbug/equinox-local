## Scope — keep this narrow

Replace the macOS AppKit/WKWebView and Windows WPF/WebView2 application shells with one shared Electron **46.0.0-alpha.5** (maintainer approved alpha.5 after discovering npm alpha.6 was not published) shell. Keep the current Control Center, its visual design, routes, translations and product purpose. No Workspace, second dashboard, embedded ChatGPT browser, provider integration or native chat product in this phase. Do not restore the reverted Electron preview.

The desired end state is one installed Equinox Local application and one backend authority, not a native shell launching an additional Electron UI. Chromium subprocesses and a deliberately owned backend/helper are implementation details, not separate user-facing products. Keep existing bounded API/capability, browser-context, consent and private-state contracts. Refactor only where needed to remove duplicate shell mechanics.

## Implementation decisions

1. Renderer remains sandboxed, context-isolated and without Node integration. Only the original loopback document can access any narrowly scoped native bridge. Deny unexpected navigation, windows, permission requests, downloads and generic execution/file APIs.
2. Keep UI adoption separate from runtime packaging. Decide process ownership from the existing native contracts rather than assuming `BrowserWindow` replaces launchd, TCC or Windows Job Objects.
3. Use the maintainer-approved exact npm pin `electron@46.0.0-alpha.5`. Do not introduce a custom binary downloader to work around alpha.6 publication lag. Verify the actual bundled Node version.
4. Do not auto-replay mutations during offline recovery. Readiness/reconnection can repeat bounded GETs; update/restart/task/chat actions cannot.

### Approved lifecycle simplification

The maintainer selected **one Electron main-process runtime owner on both platforms**, retaining only necessary small native helpers. During the installed cutover retire the old macOS launchd runtime ownership and WPF shell rather than porting their layered orchestration wholesale. Preserve login preference with the application's native login registration; close remains resident and explicit Quit stops owned backend processes. This approval is for implementation; the active Factory has not been converted.

- Reuse the existing macOS runtime wrapper/supervisor and its parent-death cleanup beneath the Electron permission-owning application. Remove the old background-host/foreground-shell split.
- Reuse the existing Windows native Job Object lease plus existing gated Node supervisor. Native shell-control compatibility retains the same-current-user pipe/mutex ABI for backend restart and installer shutdown; it must not become another UI or updater.
- Extract macOS `getsid`/session-process queries from Swift into a small non-UI native helper before removing Swift. Preserve the terminal manager's exact CLI/environment contract.
- Package Electron with its complete resources; do not weaken generic native-store symlink rejection to fit macOS framework symlinks. Decide the bundle/archive representation explicitly in the signed packaging work.
- Keep backend restart/shutdown communication on a bounded user-private local lifecycle pipe/socket, not another HTTP server or a generic execution endpoint. Preserve the Windows pipe ABI; macOS needs its Unix-socket counterpart after launchd retirement.
- Do not add an external always-on supervisor for Electron. Backend recovery is bounded while the main process is alive; application termination drains owned runtime/helpers. User launch and the preserved login setting reopen the application.
