# Main updates: immutable program replacement and external recovery supervisor

Status: **IN PROGRESS** (2026-10-11). Product code is canonical in this public repository; factory is an installation role, not a product fork. This plan deliberately does **not** publish another numbered Stable release or switch users away from admitted `main-snapshot`. Read `docs/plans/unified-main-update-channel.md` first.

## Incident and design decision

Windows 6.0.4 enrolled correctly in managed Main at A=`2207e894` but an `artifact_required` Main native update to B=`40688c9` closed the original WPF shell to replace its binaries, then sent a restart request to that terminated process's `\\.\pipe\EquinoxLocal.WindowsShell.Reopen`. Rollback used the same dead pipe, leaving a `rollback_failed` receipt and `active.json` lock. Public PR #199 (`2a2c6e6`) now uses exact verified direct WPF launch for native swaps, but older installed A cannot assume it has this new behavior. A full uninstall would remove valuable state and does not solve self-update orchestration.

**Policy:** replace *immutable executable/source slots* rather than reinstalling the whole application. Persistent config, keys, tunnel profile, workspaces, user files, browser profile and local per-user Chrome Native Messaging registration are separately owned; an updater must never replace or delete them. Compatible JS-only Main updates keep the fast `reuse_native` path. Native-impact changes install fully verified native payloads as a unit, do not copy individual files over the running shell.

## Required steady state

1. Keep signed Stable as bootstrap and known-good emergency baseline; only admitted four-target exact-SHA Main is the continuous update feed. The Chrome Web Store remains the sole Equinox Browser extension distributor.
2. Stage immutable SHA-addressed source, dependencies and signed/provenance-verified per-target native artifacts **before** touching the running binary or current pointers. No ambient user Git, npm, compilers or PATH. Retain the previous complete verified slot until health proves the new one.
3. Introduce a small, independently owned *per-user update supervisor/launcher*, outside the currently replaceable WPF/program tree and the active source checkout. It must survive shell termination, prove its own executable identity and filesystem ownership, have no general command interface, and launch only verified owned Equinox Local releases. It must never execute a newly downloaded unverified updater. macOS must preserve the stable `.app` TCC identity and LaunchAgent contract.
4. Durable journal state machine: `prepared -> native-staged -> shell-stopped -> switched -> restarted -> healthy -> committed`; each step idempotently reconciles on interruption. Persist old/target source SHA, native release identity, exact source/native pointers, worker identity and a rollback inventory, with strict size/ACL/symlink/cross-user checks. On restart after power loss, resolve the journal and current process identity **before** new updates can start. Ambiguous ownership remains blocked; never guess a successful rollback.
5. Atomically select one complete admitted program slot (or revert to the old one), start it from the independent supervisor, and verify exact source SHA **and** correct native shell/release, Native Messaging, loopback health and tunnel availability. A short positive health check alone is insufficient if the old A server is still responding. Require a bounded sustained health interval and explicitly record successful activation.
6. On any failed B activation, restore the exact A source/native/messaging registrations, relaunch verified A, test A's health, preserve B and the failure receipt for diagnosis, and only then release transaction ownership. Failure to prove A must remain loud and locked, never delete user state or silently mark success.
7. User clicks `Update & restart` once. The UI does not request tunnel credentials again and displays clear progress/rollback outcomes after reboot, not a vanished window. An independent supervisor must also be able to resume a safe update without a running Control Center. Optimize actual end-to-end GitHub Actions wall time rather than isolated step metrics.

## Milestones and gates

- **R0 — failed Main transaction recovery:** `scripts/diagnostics/recover-windows-main-update.mjs` is read-only by default; explicit `--apply` may archive **only** a `rollback_failed` transaction's exact lock after pinned managed-source/worker ownership checks, verified original source/pointer SHA, active signed-release native shell, exact per-user Native Messaging registry+manifest, and live `HEALTHY` runtime at original SHA. Recheck after stale worker cleanup. Preserve the original `rollback_failed` receipt and archived lock, never touch user data or original release. Do not invoke on the user's machine until it passes full tests and live dry-run. This is an operator remediation, not an automatic blanket unlock.
- **R1a — safer native swap rollback (initial hardening):** Windows replacement must validate the still-owned previous shell backup before recovery, quarantine—not destructively delete—the replaced candidate, explicitly report second-stage rollback failures and retain the original backup for diagnosis. This is a necessary guard for native swap errors, **not yet** independent restart/crash recovery or the final A/B design.
- **R1b — offline native swap inventory (read-only):** `inspectEquinoxLocalWindowsNativeSwap` compares the exact previous/target release shell byte trees with the fixed installed WPF directory and at most one legitimate old backup. It distinguishes untouched A, B without backup, A backup with absent program root, and B with recoverable A backup; rejects foreign/tampered trees, symlinks, multiple backups and staged/failed orphan ambiguity. The output is **not** authorization to restore or finalize a transaction. An external trusted launcher must additionally authenticate the durable transaction receipt, active worker, Native Messaging and source pointer before any action.
- **R1 — independent launcher design and implementation:** audited owner-only helper and immutable program-slot protocol, no new publicly reachable server or TCC identity; start with Windows WPF native lifecycle and explicit rollback, then macOS compatibility.
- **R1c — Windows Guardian admission foundation:** `inspectEquinoxLocalWindowsGuardianAdmission` is a read-only guard for future external launcher work. It verifies exact user-owned install roots and pinned Git path, stable and optional Main native release/SHA, the matching installed WPF files and Chrome Native Messaging owner; active update locks and detached-worker traces block selection. It does not yet ship, install or activate an independent launcher, alter startup records, or repair existing machines. The future launcher must operate outside the replaceable WPF tree and bind these checks to the real native handoff and durable journal.
- **R1d — independent Windows native Guardian bootstrap (packaged candidate, not activated):** `native/windows/EquinoxLocal.Guardian` is a separate .NET/Win32 executable published for x64/ARM64 to `runtime/guardian/EquinoxLocalGuardian.exe` in the managed release archive. Unlike the replaceable WPF tree, its intended install root is under `%LOCALAPPDATA%\Equinox Local\runtime\guardian`. Before launching it accepts only zero args, `--startup`, `--uninstall` (same managed WPF contract), or `--inspect` (no launch); validates its exact owned path, current signed Stable version and target, absence of active Main lock/native Main pointer/orphan worker, and a bounded complete SHA-256 comparison of installed WPF files against the active Stable shell (ignoring only owned WebView2 cache). The bootstrap deliberately refuses Main native transitions until an authenticated immutable native-slot/journal selection protocol is implemented. **This milestone compiles/packages the independent binary but does NOT copy it to the active user's runtime folder, modify Start Menu/ARP/Run, change Main worker restarts or authorize an installed-client update.** Package tests/CI must prove both PE architectures before migration. The next milestone installs it to the owned per-user runtime location with independent rollback, promotes registration only after real installed-host acceptance, and wires the verified Main slot selection and journal.
- **R1e — Guardian binary provisioning during Windows first install (not activated):** `provisionWindowsGuardianFromRelease` copies the exact release-local independent executable into the user-owned fixed `runtime/guardian` location, only after the managed Stable release has passed verification. It verifies the complete SHA-256 bytes before and after copying, publishes without overwriting an existing executable (exclusive same-volume hard link), and rejects symlinks, unsafe roots, mismatched existing files or source mutation. Repeat install is idempotent; older Stable releases with no guardian subfolder remain supported. The first-install runtime then launches the **existing** WPF exactly as before; no Start Menu, ARP, startup, channel, journal or update promotion changes in this milestone. This is bootstrap presence, **not** a Guardian-authorized release switch; adding the supervisor and hardened native Main slot selection remains mandatory before switching live users.
- **R2a — native handoff journal foundation (not integrated yet):** `createEquinoxLocalWindowsNativeTransitionJournal` maintains a separately persisted, bounded per-transaction Windows record that pins old/new source SHA, old Stable/Main native identity, target native contract, exact receipt start timestamp, target architecture and a generation number. It only advances through allowed install/restart/health or explicit verified rollback stages; each advancement requires the current owned Main receipt, a separate native milestone verifier, an exclusive fail-closed writer guard and durable atomic persistence. A killed writer leaves its guard in place for **manual proof of ownership** rather than quietly claiming success. The record is not itself proof of installed binary/Native Messaging identity, and the currently installed updater does not yet call it. The next task must wire this journal into the real external Windows guardian/worker at the exact native shutdown, swap, launch and health boundaries; then acceptance should kill/restart workers at every boundary and prove the old complete slot can recover. No automatic repair, startup hooks or changes to user files are introduced in R2a.
- **R2 — crash-safe journal:** staged switch/restart/recovery checks for termination during each transition, stale locks, shutdown race and startup after power loss. Require no `\\.\pipe` connection to a process the updater itself has stopped.
- **R3 — test matrix:** Windows x64+ARM64 real WPF installed-host A→B, forced B failure→A, truncated download, kill worker/shell at each stage, program/native host tampering, stale pid/PID reuse, and preserved config/tunnel/browser profile. macOS arm64+x64 LaunchAgent/TCC and Stable fallback acceptance. Match canonical exact-SHA native snapshot and CodeQL before merge. Physical Windows machine verifies Start, Control Center, Agent Browser, terminal/WinApp/tunnel and Main updates; do not close #184/#186 earlier.
- **R4 — production migration:** old installations retain their signed 6.0.4 baseline until new supervisor capability is proven. No silent uninstall/reinstall, no credentials migration by guess, no new version number for ordinary Main changes. Confirm the user's Mac mini factory running build after any production publication.

## Operator cautions

Do **not** press Update again on a `rollback_failed` installed client. Read and preserve its forensic receipt, inspect native ownership and the running baseline first. A `--apply` recovery is safe **only** when the binary executing the tool and its product-owned Git/Node toolchain are trusted, the exact dry-run is clean, and user runtime is not being concurrently updated. Never delete `active.json`, the receipt, source pointer or credential files by hand. If Windows Local access is blocked, stop at tests and leave the live Windows installation untouched.
