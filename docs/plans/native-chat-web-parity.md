# Native Chat feature parity with ChatGPT Web

**Status:** active development, NOT published or accepted. This inventory prevents confusing code compilation with finished product acceptance.

## Product contract

Native Chat is a full-featured desktop client for the person's real signed-in ChatGPT account, not an open-tab preview. Equinox owns the desktop layout, history, composer and tools. Equinox Browser bridges the consented user Chrome session, not a second API subscription, credential extractor, or quota bypass. Controls must reflect account-observed availability. All mutations bind exact browser instance, tab, conversation and provider state; uncertain sends are never replayed.

## Current source-only implementation

Browser Bridge v13 reads bounded ChatGPT navigation links and project identities from the visible DOM. It never claims this to be full account history, and does not scrape cookies, tokens or undocumented account APIs. Guarded historical selection uses the already-consented Chrome tab, refuses while generating or with a draft/attachment, and re-checks identity. Model discovery obtains the account's choices from the actual model menu; choosing an offered model or adjusting effort requires explicit confirmation. Native Chat groups conversations and exposes those controls over the authenticated private Control Center API. Explicit native Search opens a temporary inactive user Chrome tab, uses the provider's own search dialog, returns bounded matching conversations/excerpts and closes that tab. Similarly a native Project selection can expand its provider sidebar row in a disposable tab to enumerate conversations. These navigation receipts are short-lived and validated against the original Chrome session before the selected conversation can change. New Chat model/effort selections are verified on the newly created provider tab **before any initial prompt content or send**; a failed preflight must not submit the first message. Native conversation actions now use another inactive, disposable user Chrome tab for the exact account-observed conversation. Native pin and rename are read from the real ChatGPT menu, require a fresh title and verified sidebar/search identity, and return success only after the provider UI reflects the requested change. Every mutating request has a unique local action ID and is never blindly replayed. The original active task tab is never used for these mutations. Project move now validates the actual destination Project ID and unique name against the provider's sidebar and menu, and requires the provider's project-scoped URL to be observed after clicking. Archive requires a separate affirmative action in the Native Chat dialog and stable provider sidebar removal before reporting confirmation; active task-bound conversations cannot be moved or archived. Delete now requires explicit Native Chat confirmation AND the provider's own distinct destructive dialog. Provider confirmation must be unambiguous, followed by stable disappearance from the authenticated sidebar; no implicit retry after an uncertain result. Share and additional action menus still require implementation. None of the mutating actions have yet passed actual installed Factory acceptance, so this is not shipped or verified end to end.

The new read-only chat_bridge.tools_catalog method opens an inactive temporary ChatGPT home tab, inspects the provider's visible composer Add Files and More menu and closes that tab. On the user's signed-in account, this projected 7 provider tools and 3 connected apps, including Web Search, Deep Research, image creation, file attachment, Equinox Local and Gmail. The catalog is account-observed and bounded, not static or exhaustive. **Source-only progress:** Native Chat now displays the dynamic tool/app list in a first-party picker. Existing-chat messages can request the account-offered Web Search option; the bridge selects it in the actual provider composer and verifies exactly one matching inline tool pill before filling/sending the original message through a single durable receipt. Other tool/app options are shown but disabled until their distinct provider composer behaviors are implemented; they are not silently treated as Web Search. This source flow is compiled but has not yet been proven by a real installed sent turn. New Chat first-turn tool choice remains open. A source-only single-file flow now uses a trusted Electron Open File dialog and realpath/regular-file/size validation (100 MiB cap); the Browser Bridge selects the unique generic ChatGPT form file input with DOM.setFileInputFiles and requires the provider's actual named attachment card and removal control to remain stable before the existing one-shot send. File-only and captioned sends are supported in the source; source does not assert a provider upload completed from input.files alone. Native remove-before-send simply clears the local selection. A 61-byte synthetic file was uploaded into a temporary ChatGPT Home composer through the existing Browser file upload operation, its named attachment and remove button were observed and its attachment removed, and the temporary browser tab and local QA file were deleted. **The Native Chat end-to-end file send has not yet been performed or accepted in the installed Factory.** Images/multi-file/provider progress/new-chat attachments need follow-up.

Browser 1.2.6's earlier CWS ZIP is superseded as a Native Chat candidate; Browser 1.2.7 is **not submitted or published**.

## Release gates

1. Real installed macOS Chrome Browser v13 plus matching signed Source Factory proof: multiple conversations/projects, safe history switching and hydration, model/effort, drafts, blocked states and accessibility.
2. Implement the remaining product features needed for parity, especially uploads, tools, conversation actions, project mutations and account settings; obtain explicit maintainer UX acceptance.
3. Real installed Windows x64 physical acceptance, macOS signed validation; no new repo tests or fixtures.
4. Only afterward approve native publication, verify four signed targets and supply the final CWS ZIP in Downloads for maintainer submission.

**Checkpoint 48 provider tool mode discovery (2026-11-22):** The provider offers different real composer outputs. Web Search and Image Creation create typed inline system-hint pills (`search` and `picture_v2`); Deep Research, Gmail and the connected Equinox Local app create actual provider app mentions with provider-owned `app://` paths. Drawing opens a separate visual editor and is not yet enabled as a Native Chat message tool. The source now differentiates these exact account-offered types and refuses any unexpected or mixed composer state before sending. Actual compiled-source selection expressions returned confirmed provider markers for Deep Research, Image Creation and Gmail in disposable Chrome tabs, **without sending prompts**. Tool-augmented Native Chat sends are not yet accepted in an installed Factory.

**Checkpoint 47 follow-up hardening (2026-11-22):** The v13 browser content-script continuation observer and Fresh Home observer now treat modern ChatGPT attachment cards as unsent user content even when the ProseMirror text is empty. Provider history navigation and model controls also use the real attachment-card selector, preventing accidental loss or cross-message submission of files. The global search empty-result script escaping was corrected, and an actual unmatched query in disposable Chrome returned an authoritative empty result (ready, 0 items, partial false).

**Checkpoint 48 desktop boundary (2026-11-22):** Native Chat tool discovery is now explicitly allowed through the Electron read-only IPC path; the previous omission would have broken the control in a packaged app despite successful builds. File uploads from the renderer are further restricted by a one-time, ten-minute exact native Open File dialog selection in the trusted Electron main process. Only that same path/name/byte-size may cross the private Native Chat POST file boundary. The authorization is consumed before the browser delivery request to prevent ambiguous replay. The renderer also retains selected files if the user attempts to navigate while the file is unsent, and discards an OS-picker return if the selected conversation changed meanwhile. Source compile success does not establish installed Factory acceptance.
