## Product boundary

This is a first-party Electron conversation workspace served from the fixed read-only equinox://control/ origin, not an embedded copy of chatgpt.com. Current-user Chrome and Equinox Browser 1.2.5/v11 are the only ChatGPT session/browser automation route. The renderer communicates through the narrow current-user authenticated Control Center IPC.

The shared Telegram Chat Bridge controller retains exact Browser instance, tab, conversation, user epoch and turn identities. Native Chat explicitly forbids the Telegram bridge's usual same-conversation tab re-acquisition during sends and verifies the returned tab identity on subsequent reads; if the selected Chrome tab disappears, it requires user re-selection instead of silently sending through another tab. Unique send IDs, bounded text, no automatic ambiguous retry, fail-closed conversation selection, separate User/Agent Browser contexts, and no account cookie extraction remain mandatory.

Chat On Steroids (https://github.com/totec448-spec/chat-on-steroids) and Codex are the visual and interaction references. Their rich tool-event and worker timelines have separate recorded event data, whereas the current Equinox Browser Chat Bridge v11 supplies only bounded displayed messages, generating/final status, and scoped live previews. Do not fabricate provider tool events or model selectors.

## Released baseline versus quality candidate

- **Main and Source Factory:** The public snapshot is still 0fc8bf8, but the installed Mac Source Factory is now on main f317ea2, healthy after real restart and deep strict signature verified. Four CI candidates passed; publisher is waiting for maintainer approval.
- **Installed macOS transport evidence:** One new Native Chat message and a follow-up each reached one authenticated Chrome conversation once; assistant final messages, real live preview and Task Capsule binding appeared in the packaged Electron window. These prove transport, not design quality.
- **UX redesign:** merged from PR #355 to main, installed on macOS Source Factory. Full-height Chat workspace with compact icon rail only on Chat, open-Chrome-only conversation list and filter, centered readable transcript, better text/code presentation, and a docked growing composer. Existing dashboard, settings and setup retain their layouts.
- **Task Capsule context:** A drawer appears only for a task associated with the exact selected conversation. Authenticated, read-only task detail includes the real objective, checkpoint revision, completed and next steps. Public Browser context and tab binding are checked again before display; closing or switching invalidates stale reads.
- **Keyboard and timeline behavior:** Enter and Ctrl/Cmd+Enter send, Shift+Enter adds a newline. New Chat first messages must be single line with at most 1,500 characters, follow-ups at most 4,000. A keyboard-accessible "Latest messages" button appears only when the transcript is scrolled up; it returns focus to the conversation log. Scrolled-up reading positions are otherwise preserved as messages arrive. A user-selected excerpt from a completed assistant reply can be quoted into the local composer without transmitting or clearing an existing draft, subject to the same composer length and send guards. No ambiguous transmission replay.
- **Rendering:** Safe DOM text nodes for headings, lists, inline emphasis, fenced code, quotes and rules, not unsanitized innerHTML. User-requested Copy works on displayed complete messages and code blocks, never automatically. Live preview remains explicitly uncommitted.
- **Unreleased Browser v12 extension integration:** Read-only inspection of a real Chrome assistant response proved underlying H3, P, UL, LI, STRONG, CODE and A semantics were lost by the v11 innerText projection. Source extension 1.2.6 now offers optional bounded richText on the exact selected conversation recent/live/final answer, deriving only safe Markdown TEXT from one verified semantic render root. Media, multiple/unsupported roots, inconsistent content or truncation fall back to original v11 text. The installed v11 extension works unchanged; its CWS ZIP remains 1.2.5 and is not automatically published. v12 needs genuine installed extension and matching Source Factory acceptance before release. These semantic blocks are not tool-call records.
