## Initial architecture inventory (historical, before Phases 1–2)

- `src/equinox-control-center.html` currently has a large `section-chat` first-party old UI and a `native-chat-open-embedded` button; the experimental ChatGPT window is `desktop/embedded-chat.ts` invoked from `desktop/main.ts`/preload and the menu.
- The old first-party Native Chat uses `src/equinox-local-native-chat.ts`, `src/server.ts` and private IPC routes, plus Control Center TS/HTML/CSS and `chat_bridge.*` operations in `extension/service-worker.ts`.
- `src/telegram-chat-bridge-controller.ts` **also calls** `chat_bridge.inspect`, `chat_bridge.deliver`, `chat_bridge.read_final` and `chat_bridge.live`. Hence deletion scope is a product decision: deleting every such operation could break Telegram Chat Bridge. Task continuation and Fresh Chat Resume also have their own related extension functions. Keep the shared functions required by Telegram and the existing continuation mechanisms.
- Current remote ChatGPT page CSS customizations in `desktop/embedded-chat.ts` are only selection, focus outline and sidebar border; most of the screen is untouched ChatGPT Web. This is **not** an accepted Codex-style design.

5. **Feature accessibility:** Every provider feature remains accessible; its placement may change for the design. Do not exhaustively retest inherent ChatGPT Web features as if Equinox implemented them.

7. **Telegram:** Preserve all functions Telegram needs. Remove old Native Chat-specific code from EL and extension, not shared Telegram dependencies.
8. **Continuation:** Preserve current Auto Continue, Fresh Chat Resume and Task Capsule integration to keep ongoing Chrome-based development working. Integrate equivalent functionality directly into the new native Chat, using the owned embedded view and less fragile local integration. Only remove obsolete Chrome-dependent continuation paths when the new native workflow is genuinely reliable end to end and Chrome is no longer needed for working with the agent through EL. Never interrupt the active task tab; preserve current isolated provider session and user data.
9. **Review:** Owner is sleeping and does not require intermediate screenshot approval. Exercise care, avoid AI-slop aesthetics, and perform visual review against the reference independently. Keep public distribution gated until the full implementation and relevant acceptance are complete; use the normal Factory update path, and retain owner-controlled CWS submission.
